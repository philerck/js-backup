Eventweitergabe

Wenn im Browser ein Ereignis (Event) auftritt – zum Beispiel ein Klick auf einen Button –, dann passiert im Hintergrund mehr, als man auf den ersten Blick denkt. Das Event betrifft nicht nur den Button selbst, sondern es „wandert“ durch die gesamte Struktur der Webseite, also den DOM-Baum (Document Object Model).

Man kann sich den DOM wie eine Familie vorstellen: Ein <div> ist das „Elternelement“, in dem sich eine <section> befindet, und in dieser liegt ein „Kind-Button“. Wenn man auf den Button klickt, können alle Ebenen – Eltern, Kind und sogar Großeltern – etwas davon mitbekommen.

Dieses Durchlaufen des DOM nennt man Event Propagation (Ereignisweitergabe). Sie besteht aus drei Phasen:

  1. Capturing Phase – das Ereignis läuft von außen nach innen (von document bis zum Ziel).

  2. Target Phase – das Ereignis erreicht das Ziel-Element.

  3. Bubbling Phase – das Ereignis läuft vom Ziel wieder nach außen (von unten nach oben).

Event Capturing

In der Capturing-Phase läuft das Event durch alle Eltern-Elemente von außen nach innen. Man kann sich das wie Eltern vorstellen, die bemerken, dass im Haus etwas passiert, bevor das Kind selbst reagiert.

Wenn man möchte, dass ein Event schon beim Hinabsteigen durch den DOM-Baum erkannt wird, kann man das in addEventListener() festlegen. Dazu nutzt man den dritten Parameter (oder ein Optionsobjekt). Wird dieser auf true gesetzt, wird der Listener in der Capturing-Phase ausgeführt.

<div class="parent">
  <section class="child">
    <button class="btn">Klick mich</button>
  </section>
</div>

const parent = document.querySelector(".parent");
const child = document.querySelector(".child");
const button = document.querySelector(".btn");

// true = Capturing-Phase
parent.addEventListener("click", () => {
  console.log("DIV (Parent) - Capturing");
}, true);

child.addEventListener("click", () => {
  console.log("SECTION (Child) - Capturing");
}, true);

button.addEventListener("click", () => {
  console.log("BUTTON - Target");
});

Wenn man auf den Button klickt, zeigt die Konsole:

DIV (Parent) - Capturing
SECTION (Child) - Capturing
BUTTON - Target

Das Event „läuft“ also von oben (Parent) über das Kind (Child) bis zum Ziel (Button).

Event Bubbling

Nach dem Ziel-Element beginnt die Bubbling-Phase. Das Event „blubbert“ von unten nach oben, also vom Kind über alle Eltern zurück zum document. Wenn man nichts angibt, arbeitet addEventListener() standardmäßig im Bubbling-Modus (also false).

const parent = document.querySelector(".parent");
const child = document.querySelector(".child");
const button = document.querySelector(".btn");

// false oder weglassen = Bubbling-Phase
parent.addEventListener("click", () => {
  console.log("DIV (Parent) - Bubbling");
});

child.addEventListener("click", () => {
  console.log("SECTION (Child) - Bubbling");
});

button.addEventListener("click", () => {
  console.log("BUTTON - Target");
});

Wenn man wieder auf den Button klickt, zeigt die Konsole:

BUTTON - Target
SECTION (Child) - Bubbling
DIV (Parent) - Bubbling

Das Event startet beim Button und wandert dann wieder nach oben.

Capturing und Bubbling einsetzen

Das Wissen über diese beiden Phasen ist nicht nur theoretisch interessant – man kann es gezielt für eigenen Code nutzen, um Verhalten im DOM zu steuern oder zu vereinfachen. Im Folgenden werden drei typische Situationen gezeigt, in denen man Capturing oder Bubbling bewusst einsetzt.

Beispiel 1: Event Delegation mit Bubbling

Wenn man viele Buttons in einer Liste hat, muss man nicht jedem Button einzeln einen Event-Listener geben. Stattdessen kann man den Listener auf das übergeordnete Element setzen – und das Event „blubbert“ automatisch dorthin. So spart man viel Code und kann zentral reagieren.

<ul class="menu">
  <li><button>Home</button></li>
  <li><button>Kontakt</button></li>
  <li><button>Über uns</button></li>
</ul>

const menu = document.querySelector(".menu");

menu.addEventListener("click", (event) => {
  if (event.target.tagName === "BUTTON") {
    console.log("Button geklickt:", event.target.textContent);
  }
});

Wenn man auf einen Button klickt, „blubbert“ das Klick-Event nach oben und wird vom <ul>-Element erkannt. Dadurch kann man mit nur einem Listener alle Buttons abdecken, statt jedem Button einen eigenen zu geben. Das funktioniert, weil das Bubbling standardmäßig aktiv ist.

Beispiel 2: Frühe Erkennung mit Capturing

Manchmal möchte man Ereignisse abfangen, bevor sie das Ziel erreichen, etwa um bestimmte Klicks zu verhindern oder vorzeitig zu reagieren. Dafür kann man die Capturing-Phase nutzen, indem man true als dritten Parameter bei addEventListener() angibt.

<button class="btn-capture">Klick mich</button>

const button = document.querySelector(".btn-capture");

document.addEventListener("click", (event) => {
  console.log("Document hat den Klick zuerst erkannt");
}, true); // Capturing aktiviert

button.addEventListener("click", () => {
  console.log("Button wurde tatsächlich geklickt");
});

Wenn man jetzt auf den Button klickt, erscheint zuerst Document hat den Klick zuerst erkannt und danach Button wurde tatsächlich geklickt.

Das liegt daran, dass das Document durch das Capturing schon reagiert, bevor das Event beim Button angekommen ist. So kann man Ereignisse frühzeitig analysieren oder filtern, bevor sie überhaupt beim Ziel-Element ausgelöst werden.

Beispiel 3: Weitergabe stoppen

Manchmal möchte man nicht, dass ein Event nach oben weitergegeben wird – z. B. wenn man sicherstellen will, dass ein Klick nur innerhalb eines bestimmten Bereichs wirkt. Dafür gibt es die Methode event.stopPropagation().

<div class="parent">
  <section class="child">Klicke auf mich!</section>
</div>

const parent = document.querySelector(".parent");
const child = document.querySelector(".child");

parent.addEventListener("click", () => {
  console.log("Parent wurde angeklickt");
});

child.addEventListener("click", (event) => {
  console.log("Click auf SECTION, aber stoppt hier!");
  event.stopPropagation(); // verhindert die Weitergabe nach oben
});

Wenn man auf die Section klickt, wird nur die Meldung Click auf SECTION, aber stoppt hier! ausgegeben – die Meldung des Parents erscheint nicht. Das Event wird also an dieser Stelle gestoppt und blubbert nicht weiter.
